# @deepseek-ai/dsh-client-ui-slark-agent

[English](README.md) | 中文

## 概述

在 Slark Desktop 的 DSH 会话中输入 `@`，可查找获分配的企业 Agent。选择 Agent 并发送纯文本问题后，会创建 Slark 任务；结果显示在同一会话中。Agent 列表要求 Account Profile 在线，并且 Desktop 桥确认当前可调用。

## 使用此包

Web bundle 自动挂载此包，无需额外配置。Desktop 启用项目范围模式后，输入区提供 Slark 协同按钮，打开现有右侧栏。侧栏管理项目范围、Agent 目录和工作区协同历史；聊天保留原输入框。为当前 DSH 工作区多选 Slark 项目空间并应用；取消关闭侧栏并丢弃未应用的项目选择，未配置工作区默认不选任何空间，未归属工作区的会话不能设置范围。Agent 名称带项目空间名称。点击目录中可用的 Agent 会在普通输入框的当前选区插入结构化 mention，并把焦点返回聊天，不发送消息。窄窗口中，成功插入后关闭全屏侧栏。草稿过期、Host 或会话变化、Agent 不可用或范围没有已保存的选择时不会插入。项目选择草稿在应用前不改变可插入的对象范围。Main 启用新版提交且服务端确认目标支持独立执行后，在聊天中输入 `@`、从这些空间明确选择最多十个 Agent，并用自然语言描述各自任务即可发送，无需打开面板、填写任务表单或确认预览。其他目录项仅供查看；范围模式拒绝旧 Agent 引用和旧调用。日常聊天无需打开该区域。

范围与执行能力分别声明。仅提供范围的桥注册项目管理，不启用结果轮询或 Agent 提交；完整执行桥才启用这些消费者。

在已有单目标模式下，在 Slark Desktop 中输入 `@`，在 Slark 企业 Agent 分组下选择 Agent，并发送纯文本任务或问题。选中的芯片可位于句子任意位置，显示为 `Agent · 项目空间`；候选描述还显示所属企业。例如，在「请 @Guide · qiu-slark 检查登录问题」这句话中选中 Guide。任务区在原会话显示结果；未完成任务经过 120 秒后标记为后台任务。

在范围模式下，不明确的请求会在输入框旁显示已保存的自然语言问题。直接在同一输入框回复，无需再次插入 Agent 芯片；回复只接续原先明确提及的目标。客户端从当前 Profile 的完整有界会话列表发现未决原消息，再向 Main 读取各计划的当前状态；协同记录也会直接恢复这些问题，无需操作面板。有多个未决请求时不会代选。回复身份绑定原 Source、计划、未决项和完整文字，不包含变化的计划修订号，因此重新加载后相同回复仍保留同一身份。只有经过验证的 Main 受理结果或已提交回复结果才消费回复草稿；结果不明确时保留草稿。新 Agent 目标仍需明确的芯片。

## 了解实现

<details>
<summary>实现细节 — 点击展开</summary>

Client 来源通过 Desktop 桥读取绑定当前账号的分配。每个编辑器芯片保留分配、项目、Agent、企业和发布版本；Slark 在调用准入时再次检查分配授权。来源为单个结构化 Agent 芯片认领整条草稿，问题仅移除该芯片，并拒绝普通模型序列化。发送失败保留草稿，重试时重新裁决。新引用通过 Web Crypto SHA-256 将准入键绑定到问题内容：原样重试复用键，修改问题后生成新键；旧引用保留原有键和芯片文字。Web Crypto 不可用时拒绝提交。旧芯片的准入键若不是字符串，引用解析时即拒绝该芯片。范围投影通过输入区注册提供的框架快照 hook 观察 Workspace Controller 中的真实会话归属。入口与侧栏共享当前 Session Controller 的投影；Controller 替换时释放原投影。归属或桥接身份变化时清空缓存并忽略迟到响应，每次保存后重新读取权威范围。保存冲突或结果不确定时不重放草稿。项目和 Agent 分页保留显式续页状态；可见项目为空仍可能有下一页，未加载的已选空间也保留选择。Desktop 桥只提供目录摘要。不发布 companion。

目录读取在请求前和响应后都要求范围以及执行或根规划模式可用。每个范围引用保留选择时的工作区、会话、目标、能力摘要和一个 UUID。第一次明确选择建立共享的原始 Source 身份；后续芯片保留该身份，即使第一个芯片被移动或删除也不改变。每个芯片携带各自的 mention ID 和 UTF-16 范围。整条原始草稿传给 Main；页面不提供 owner、凭据、模型或 Task ID。发送结果不确定时保留草稿和 Source 身份，编辑文字不会生成替代 Source；Main 与 Native 拒绝已捕获身份的内容变化。已有范围芯片全部移除后，再明确选择 Agent 才建立新的用户请求。工作区、归档或桥接身份变化，以及错误来源或迟到响应，都不能清空原草稿。Main 负责分析、冻结和受理；受理不等于执行完成。 经过验证的讨论路由通过当前普通 Session prompt 发送未经改写的原文，并使用 Source 派生的稳定请求 ID。回复不确定时保留草稿，重试沿用同一身份。Agent 芯片仍不能进入普通序列化。

根规划模式只认可包含原 Source 和合法 root/trace ID 的 `planning_recorded` 回执，显示“规划已保存，尚未开始执行”及追踪编号，不发送执行受理事件。响应不确定或不匹配时保留草稿和原 Source 身份。

新版结果区域通过 Native 的只读 `session.collaborationSources`，分页读取当前工作区内未归档会话的完整原消息，再从 Main 的 `collaborationDeliveries` 读取每条 Source 的授权结果。先读取当前会话，再按会话标识顺序读取其他会话；每个会话保留自己的 Native 游标。该 React 无关模型在工作区成员、桥或 Connection generation 变化时清除记录和游标，每个视图同时只执行一项只读查询。工作区任一成员会话的受理事件与 3 秒轮询自动刷新；清空所选 Slark 项目范围仍可读取历史。手动加载的历史页在刷新后保留，较旧投递版本不会回退已有投递状态。读取消息或结果分页期间，历史分页按钮禁用。每条原消息独立保留 60 秒窗口，用于投递与计划读取；最多并发读取两条，结果仍按 Native 页面顺序排列。整项查询的时间预算包含已加载的原消息页与回复页。单条原消息不可用时，仅清除该条回复组；成员、桥或 Connection generation 变化仍清除完整视图。读取受限时移除答案和名称；完整纯文本结果按 `Agent · 项目空间` 显示，执行终态与投递状态分别处理。没有回复或澄清问题时，区域显示当前经过验证的规划状态，包括失败、取消和讨论。计划读取失败会清除此状态；仅有冻结计划不代表任务已执行或受理。此读取不提交任务、不签署回执，也不证明 Host 已持久保存结果。

原消息定位先重新校验已显示的不可变快照，再打开其原会话并以共享焦点环颜色聚焦对应记录。较旧的定位消息在分页与刷新后保留，刷新时重新验证读取权限；权限失效时移除。定位失败在协同区域说明，插件卸载后失去定位权限。定位不发送聊天、不提交任务，也不激活模型。

</details>

<a id="model-experience"></a>

原 Chat 视图与工作区历史使用独立的只读模型。已挂载的输入区先于 Chat 视图初始化只读协同活动，因此仅有协同记录的会话在打开或重连后显示原文和回复。Source 页面为空时保留空会话；Source 读取失败时显示现有的历史不可用状态。会话不再被观察时停止活动订阅。按需读取的 Source 位置将完整原消息和独立身份的回复放到普通聊天行旁，无额外输入框或任务表单。没有位置的旧原消息显示在带标签的历史区域。原消息和回复分别分页；已验证的定位只聚焦原消息一次。查看、刷新或关闭展示不会派发任务、确认回复或启动本地模型轮次。

## 模型体验

间接通过 Session Controller 的原始协同 Source 分析进入模型；普通聊天序列化仍拒绝 Agent 芯片。

#### KV Cache 影响

Session Controller 为每条 Source 分析组装独立请求；此插件不增加普通会话历史前缀。

## 已知限制和待办事项

<a id="known-limitations-and-deferred-work"></a>

Agent 提及依赖当前账号的 Slark Desktop 桥报告可调用。没有该桥时，普通 `@` 引用仍可使用。

- **仅 Desktop 可用的目录** — 独立的 DSH 浏览器会话无法列出或调用 Slark Agent。
- **范围模式仅支持纯文本** — 每次最多明确选择十个 Slark Agent 芯片并提供非空纯文本问题；混合引用、附件及重复芯片身份会被拒绝。旧模式只接受一个 Agent。
- **协同 2.0 联调待完成** — 范围、执行和根规划开关默认关闭。根规划保留原始 Source 和 trace，具体任务需经过 Main 持有的预览与确认。原 Session 结果读取已接入。真实 Provider/GUI 验收、获授权续跑、签名消费回执和显式引用仍待完成；范围模式不回退到旧调用入口。

根规划模式选取的范围引用在草稿内保留 `submission_mode: planning`。关闭新规划后，再提交该保留草稿只调用 Desktop `collaborationRecover`，即使旧执行模式仍开启。恢复能力缺失或规划回执不确定、不匹配时保留草稿，不启动普通聊天或旧执行。这条路径恢复本地已确认受理的根，不提供成功清空草稿后的历史根浏览。

根规划模式下，原消息结果区可通过 Desktop Main 预览已冻结的具体任务。查看预览不会执行任务；确认某个已展示任务时，使用 Main 保存的原选择提交。响应不明确时可核对状态，核对不会再次受理。原始 Trace ID 保持可见。账号、窗口、工作区或 Connection 变化后清除旧界面状态，Main 预览五分钟后失效。环境未启用执行时只能预览。受理、执行完成和原 Session 消费仍是三个独立事实。

对于任务已包含在 Main 保留预览中的可读结果，结果区提供“结合结果继续原任务”和独立状态核对。只有显式续跑请求首次消费授权；刷新和状态核对不唤醒 Agent。结果未知时禁用再次续跑。界面区分上下文已持久消费与已观察到助手后续回复；两者都不表示根任务已完成。
