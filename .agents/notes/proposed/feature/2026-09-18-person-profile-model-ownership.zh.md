# Agent Note: 旧模型凭据归属于 Person Profile

Status: proposed

[English](2026-09-18-person-profile-model-ownership.md) | 中文

## 问题

固定的 OS 用户 `.dsh` 主目录早于经过认证的 Person Profile。其中的凭据和模型设置没有账号归属。将它们导入第一个激活的 Profile，会让该账号在用户未确认时控制所有提供方。独立的 Profile worker 目录和空启动环境能隔离新输入的凭据，却不能纠正旧数据导入。

## 提案

固定旧数据导出器迁移会话、工作区和非模型设置，同时保留所有凭据及模型设置命名空间。导出器读取并校验原始文档，不改写它们，并携带被保留数据的摘要，以便在盘点确认时发现来源并发变更。这样可以阻止新导入静默分配凭据，也不改变普通 Profile 间迁移。

DSH 的模型设置将为已认证 Person Profile 提供按提供方操作的脱敏认领入口。认领会检查来源所有权和代际，将该提供方凭据及对应路由提交到当前 Profile，并在路由可用前记录唯一归属。失败或中断后保留原文件和可重试状态。同一账号可以幂等重试；其他账号收到冲突。已有 Profile 代际中自动导入的旧数据，还需单独的升级迁移，之后 Desktop 才能启用个人模型复用。

## 考虑过的替代方案

**随工作区迁移所有旧凭据。** 这延续原有行为，但会把没有账号归属的凭据隐式交给首个登录账号。

**传输后删除旧文件。** 这会阻断后续认领，而且迁移中断可能造成永久丢失。原文件应继续作为认领来源。

## 验收标准

- 新的旧数据迁移完成后，两个账号在显式认领前都无法使用任何提供方凭据及模型路由；工作区、会话和非模型设置仍可用。
- 认领一个提供方后，只有确认的账号能使用它；第二个账号无法认领或读取。重复及中断认领均可确定性恢复，且不回显明文。
- 在 Desktop 启用个人模型复用前，已经自动导入凭据的 Profile 代际也完成安全迁移。
- macOS 和 Windows 已安装产物执行相同的账号与来源归属规则。

## 风险

保留模型数据意味着迁移后的 Profile 暂时不能调用旧模型。已有 Profile 代际也可能已经包含导入凭据。认领界面和升级迁移完成前，本提案不能视为完整交付。
