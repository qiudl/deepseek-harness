# Agent Note: 绑定 Profile 的扩展操作回执

Status: implemented

[English](2026-09-12-profile-extension-receipts.md) | 中文

## Problem

REQ-20260912-0004 将 Desktop Hub 市场嵌入 Slark。Hub 的独立运行默认目录无法识别当前由 Host 管理的 Person Profile。包安装或配置写入中断时，即使调用方没有收到结果，也可能已经产生副作用。

## Decision

[操作所有者](../../../../packages/host/desktop-host/src/extension-operations.ts) 将确认计划绑定到已授权的 Profile 及其配置修订值，并在启动执行器前保存私有、经过 fsync 的持久回执。回执不保存安装载荷或异常消息，因为二者都可能包含凭据。每个计划仅接受一个操作 UUID；重试返回已有回执。

Host 根据有效窗口租约、当前运行时代数，以及在线或本地专属可写授权解析扩展权限。离线恢复权限不足以执行安装。执行器接收实时授权检查函数和取消信号；必须在每次副作用前检查授权，并在返回前等待子进程完全停止。

同一 Profile 的操作串行执行。执行器异常可能发生在写入之后，因此结果记为未知。未知结果会阻止该 Profile 的新写入和已排队写入。进程重启后，未完成回执转换为未知，且不会重放。取消不会覆盖执行器已经确认的成功结果。释放操作所有者时，会中止已接受的工作并等待其结束，然后才可释放 Host 锁。

## Alternatives considered

**使用 Hub 默认 Profile 目录。** 这些目录对应独立启动器，而非 Slark 当前窗口授权的 Profile，可能写入错误目标。

**原样复用 Session 命令日志。** 其执行器异常路径记录失败，未区分扩展操作可能已经产生的部分副作用，也不具备扩展取消生命周期。

**重放未完成写入。** 缺少最终回执不能证明包安装或配置写入没有发生；自动重放可能重复或重叠执行副作用。

## Consequences

[组合测试](../../../../packages/host/desktop-host/tests/extension-operations.spec.ts) 使用真实 Host 租约和真实文件写入，验证目标授权、重复提交、修订冲突、取消、不含敏感载荷的回执和未知结果。私有回执读取拒绝符号链接、硬链接、不安全权限、损坏数据和非 UUID 路径。

`UnixHostServer` 仅在配置执行器后开放经过协商、绑定租约的扩展命令。启动组合安装 MCP 执行器，socket 断连会中止其已接受的操作。[认证 socket 测试](../../../../packages/host/desktop-host/tests/extensions-wire.spec.ts) 提交安装，通过真实 Loader 加载写入的配置，再调用发现的 MCP 工具并收到 `pong`。第二条认证连接在证明同一 Profile 后可查询同一回执；借用其他连接的租约会被拒绝。

MCP 执行器使用未修改的 MIT 许可 Hub 源码及可重现的 ESM 生成副本。适配层拥有私有原子写入、启动失败策略和补偿。它重启 worker，避免把旧配置的激活状态误认为新安装成功，然后通过经过认证的 worker API 等待 MCP 行激活。重载失败时，恢复原内容并确认重载后才报告失败；遇到并发修改、授权撤销或恢复失败时，结果保持未知。该补偿恢复配置，不承诺撤销 MCP 子进程或远端服务的任意副作用。

worker 生命周期按 Profile 串行，防止并发确保运行产生第二个子进程，也防止释放时漏掉正在启动的进程。worker 重启后，Desktop 必须重新打开视图。插件执行和发行运行时固定版本尚未交付。Slark 开发分支已提供 broker、本地 HTTP 端点、安装协调器及按能力开放的 Hub UI。完整 Profile 迁移保留、杀进程恢复、Windows 行为和未知回执人工核对仍未验证；这不是完整的 M2 发布。

## Slark 联合验收

运行 `extensions-wire.spec.ts` 时将 `SLARK_EXTENSION_ACCEPTANCE_ROOT` 设为 Slark 源码工作树，可让测试专用客户端经过真实 Slark broker、认证 HTTP 端点、Desktop client、Hub 安装协调器与持久操作号记录。独立构建的 Host client 连接本测试服务；安装后的 MCP 工具必须返回 `pong`，重开使旧 context 失效，另一 Profile 无法读取回执。夹具提供 peer attestation 与视图 activation 元数据；不验证签名、桌面安装包或真实浏览器 worker。修正夹具后连续十次联合运行通过；此前一次刷新失败未复现，仍需安装包生命周期验证。

## 技能发布与生效确认

内部 Skill 执行器从固定版本的 Hub 源码提取未修改的 Markdown、ZIP 路径和 GitHub URL 解析声明，并以可重现的哈希检查校验。执行器负责解析 Profile 并以私有权限独占发布，调用方提供的确认函数负责验证运行时发现。这使可复用的 Markdown 处理独立于 Hub 的默认目录假设。新建安装不会覆盖已有技能；发布或确认结果不确定时保留未知回执并禁止重放。部分发布可能留下需要核对的自有目录。

[Skill 组合测试](../../../../packages/host/desktop-host/tests/profile-skill-executor.spec.ts) 加载真实 Cordis 技能注册表和文件系统提供方，验证安装后的名称、内容、来源路径和调用标记，同时验证隔离、不安全路径、并发写入、取消和持久未知结果。启动组合将 Skill 和 MCP 执行纳入同一修订值和操作队列。Slark 市场 UI 在相应 Host 清单查询成功后开放 MCP、新建 Markdown 技能及模板安装；GitHub 市场资源包另需显式的 `skill_archives` 支持。

[运行时观测校验器](../../../../packages/host/desktop-host/src/skill-runtime-ack.ts) 拒绝名称相同但路径、来源、正文、路由元数据或调用权限不同的技能。它读取不按调用权限过滤的定义，因为会话命令清单会排除仅允许模型调用的技能。回调未返回定义时，回执保持持久未知状态。worker 接口先解析默认预设的 standing scope 再返回定义；全局清单不能证明预设可见性。

[Skill socket 组合测试](../../../../packages/host/desktop-host/tests/skills-wire.spec.ts) 通过认证 Unix client 提交计划，写入 Profile 技能，再经 HTTP、生成的 RPC 分发、真实默认预设与文件系统提供方读取定义。定义在全局注册表中不存在，但在预设作用域中可见。重复提交仅执行一次确认，另一 Profile 无法读取回执，期间发生的 MCP 编辑会使 Skill 计划失效。夹具提供 Cookie 认证和 peer attestation；原生 worker 启动、浏览器刷新和打包仍需安装后的应用验收。

Skill socket 测试也接受 `SLARK_EXTENSION_ACCEPTANCE_ROOT`，其子进程运行真实 Slark broker、本地 HTTP 端点、Desktop client、共用安装协调器和持久 UUID 日志，并验证回执恢复、视图 context 更新和 Profile 隔离。Electron 单独验证 Hub 新建/模板按钮及断连处理；该夹具不显示真实 Main 确认框，也不启动打包 worker。

Main 复用固定版本的 Hub GitHub URL 解析器，在系统确认前对有大小限制的下载计算摘要。Host 再次下载确认的 URL 并核对摘要，因此分支变化不能悄悄替换已批准的字节。这使资源包数据不进入 32 KiB 控制载荷，同时保留脚本、参考文件和原始元数据，代价是下载两次；不尝试重定向、替代分支或 ClawHub 单文件回退。资源包校验、独占发布和运行时核验由 Host 执行器负责。

共用的[运行时观测器](../../../../packages/host/desktop-host/src/plugin-runtime-ack.ts) 要求每个预期条目 ID 恰好对应一个模块名相同、已启用且处于 active 状态的行。启动失败或标识重复会拒绝确认；条目缺失、禁用或模块不匹配时，保持未确认直至取消或超时。MCP 通过此观测器提交固定模块标识。插件命令完成与运行时证明相互独立，包管理器退出码不能单独形成安装成功回执。

[官方 CLI 集成夹具](../../../../packages/host/desktop-host/tests/plugin-command-integration.spec.ts) 通过 `HOST_PLUGIN_ACCEPTANCE_PNPM` 指定真实 pnpm 入口，并要求已构建的 DSH CLI。本地回环注册表提供一个测试组合包；CLI 安装它并更新 bundle 清单，再由真实 Profile 加载器与 Cordis 运行时挂载其配置层并生成激活标记。postinstall 标记保持不存在。这覆盖 pnpm 11.17.0 下的本地注册表安装，不验证随安装包发布的包管理器产物、第三方构建或原生桌面确认框。

[插件执行器](../../../../packages/host/desktop-host/src/profile-plugin-executor.ts) 复用同一持久操作管理器，在包管理器写入前校验来源与版本指纹。安装失败可能改变多个包管理器文件，因此激活失败保留为结果未知。CLI 测试同时验证重复提交不会重复安装，以及回执恢复。启动流程在集成端提供 pnpm 时注册执行器；原生确认仍由集成端负责。

[组合包贡献选择器](../../../../packages/host/desktop-host/src/plugin-bundle-entries.ts) 使用 app-boot 分别合并包含和不包含安装层的配置，并依次应用 Profile 与主目录覆盖。启动流程通过稳定的 `include:` Loader ID 前缀，在新 worker 中检查发生变化的已启用根条目。无可观察变化、分组、禁用或条件条目及被移除条目均无法确认。MCP 配置 ID 也映射到实际启动 include 的运行时 ID。pnpm 启动字段决定是否注册插件执行器；全部已配置安装器共用组合版本指纹和回执队列。

[真实插件 socket 测试](../../../../packages/host/desktop-host/tests/plugin-wire-fixture.ts) 保留实际包管理器命令、签名 socket 消息、Profile 租约、新 CLI worker 和认证运行时响应。失败或未变化的 worker 代次不能确认安装。Slark 子进程重新建立扩展上下文读取回执，并证明另一 Profile 无权读取该回执。外部目录预检与原生同意仍明确由测试替代。源码客户端从声明 TypeScript 启动器依赖的 Desktop 包解析该启动器。

MCP 删除沿用安装操作的准备计划修订、租约检查、串行执行和回执归属。Hub 仅删除本地声明的 MCP 行；新 worker 必须不再包含其 Loader 条目，才能确认成功。删除确认失败时，若授权和文件修订仍允许补偿，则恢复原配置并确认其重新生效。

MCP 编辑通过 Hub 的 `updateMcpRow` 替换一个现有同名行。Main 确认完整替换（包括凭据字段），不向市场 renderer 返回已保存的配置。拒绝改名、隐式创建、多服务更新和不支持的传输类型。Loader 组合测试将 MCP 更新为第二个端点，并验证后续调用到达新端点而非旧端点。

技能调用开关保留 Hub 的字段级 AST 修改语义，读取、原子发布、修订检查及补偿由 Host 拥有。模型与用户开关彼此独立。成功要求所选默认预设中不按调用权限过滤的技能定义与新文件一致；被遮蔽或陈旧的定义不能确认成功。清单显示本地文件标记并沿用不透明的 flat/bundle ID，不返回文件系统路径。

Markdown 导入不通过新建表单重新生成源文档，避免丢失表单字段之外的元数据。Main 将有大小限制的所选文件字节按严格 UTF-8 解码并复用 Hub 解析器；Host 独立验证名称和元数据，通过现有独占新建安装器发布，并在默认预设中核验原始内容。renderer 不传递来源路径，新文件导入不能授予覆盖权限。

同名 Markdown 替换在系统确认前绑定所选不透明条目 ID。Main 在准备前拒绝名称不符、条目缺失和不支持的 Host。Host 独立验证替换内容，复用带修订检查的编辑与恢复路径。测试覆盖另一个同名条目不变、附件保留、取消不提交、生效确认失败后恢复，以及真实默认预设 HTTP/Unix 组合中的替换。资源包整体替换仍不支持。

技能删除只移除一个自有条目，不清除所有同名定义。现有不按调用权限过滤的默认预设读取在清理前确认缺失或其他来源接替；有界来源分类随回执持久保存并传到 Desktop 历史查询。真实 HTTP/Unix/Slark 组合测试安装、更新、删除本地技能，同时保留实际 user-agents 同名后备版本。并发恢复测试保留新作者内容和原暂存文件。完整的实时来源/遮蔽清单及恢复界面仍待实现。

Hub 手动启停编辑的是插入模块行，而已安装 DSH 插件包还会自动贡献配置层，仅复用插入行删除无法证明插件包已停用。因此启停规划器通过真实组合识别独立贡献，发布 disabled 覆盖并拒绝共享修改。Loader 测试验证真实插件副作用的启用/停用/再启用，另一个服务保持可用；运行时清单测试要求精确条目已禁用且没有 fiber，执行器测试验证原字节恢复和包登记不变。Desktop 开关及真实 CLI worker 夹具已接通；签名安装包验收仍待完成。

真实跨仓夹具现已覆盖安装 0.0.1、停用/启用、更新为写入不同执行标记的 0.0.2，以及卸载。五次 worker 重启和精确运行时清单检查验证生命周期，另验证持久回执查询和已安装条目消失。卸载最初暴露 pnpm 11.7 拒绝 --ignore-scripts，已改用支持的配置选项并加入生命周期哨兵回归。Electron 以注入 provider 检查更新入口/取消/成功及卸载；系统确认与授权由 Main 协调器执行。签名 macOS 及 Windows 验收仍待完成。

MCP 恢复需要原操作持有的持久配置正文，因为回执摘要本身无法在中断后重建配置。执行器先写入私有备份，再记录不可变检查点，最后发布配置。恢复将检查点与当前修订绑定到新的确认和 UUID；阶段元数据不能单独证明文件或运行时状态。原文件缺失区别于空文件，恢复旧条目时还必须证明新增条目消失。存在冲突或无法核验时保持未知；成功恢复通过关联历史回执记录，不改写历史结果。测试覆盖发布中断、核验中断后显式重试、备份完整性和真实 Unix/HTTP/Slark 恢复流程。操作系统强杀及签名应用验收单独验证。

插件启停恢复与包管理器修复分开，因为配置备份无法重建中断的依赖事务。变更前后修订覆盖清单、锁文件、策略文件及覆盖配置，包括原配置文件缺失状态。核验备份和两种修订视图，防止在依赖状态变化后恢复过期启停策略。新的确认操作恢复或重新核验原配置，随后在重启后的 worker 中观察启用与停用条目。真实 CLI/Slark 夹具在第三次启停发布检查点后注入中断，不额外安装包即完成恢复，之后继续更新和卸载插件。异常注入验证恢复协议，不等于操作系统强杀或签名安装包验收。

部分包事务沿原请求目标继续完成，不描述为回滚。命令执行前的持久意图固定包、动作和来源；无关输入保存摘要，原依赖引用也仅保存摘要。重试前的新确认绑定当前完整修订。锁文件可能包含合法的部分写入，因此绑定当前计划，而不作为不可变的变更前边界。原意图约束目标，Host 在命令后再次检查无关输入。依赖已从清单删除时，需要修复依赖图并仅清理目标组合包登记，因为仅重复 remove 无法补回 CLI 丢失的变更前依赖成员信息。完成关联与恢复关联分开，原结果不改写。真实 CLI/worker/Slark 夹具验证安装、更新和卸载中断后的继续执行且脚本禁用；另以运行时失败注入验证未知继续操作的显式重试。
