# Agent Note：Slark Device 文件系统提供方

状态：已实现

[English](2026-08-27-slark-device-filesystem-provider.md) | 中文

## 问题

Slark 云端组合需要让 Harness 文件工具操作用户在自己计算机上选定的目录。云端进程无法直接使用该本机路径；暴露路径或静默挂载 `fs-local` 都会破坏信任边界，也会违背用户认为工作发生在所选设备上的预期。

## 决策

在现有能力 seam 处分割集成。`dsh-slark-device-client` 负责内部 Gateway 传输、操作级身份、持久任务幂等、长轮询、取消、输出游标和 SHA-256 校验。`dsh-fs-slark-remote` 通过该客户端实现不变的 `FileSystem` 服务。

提供方只暴露一个虚拟 POSIX 根：`/workspace/<workspaceHandle>`。请求只携带规范化相对路径、不透明 target key、Workspace Grant 围栏和操作 payload。读取采用原始 base64 分页，首页之后附带 expected-version 围栏；提供方负责跨分页 UTF-8 解码和二进制抽样。写入与编辑保留服务的可选防护，包括无条件变更，并使用独立于传输幂等键的副作用键。

不存在本地回退。身份缺失、设备不可用、工作区变化、输出缺口，或数据畸形、摘要无效都会产生类型化失败。这样，当用户设备权限缺失时，云端运行单元无法观察或修改无关的服务端文件系统。

## 结果

- 现有面向模型的文件工具和观察政策无需修改 schema。
- 设备本机绝对路径不会进入云端任务或模型可见结果；进程坐标保持虚拟形式，并与后续远程 shell 提供方一致。
- 含糊的创建重试只使用一个幂等键。task ID 一旦存在，重试只查询该任务，因此传输不确定性不会重复变更。
- 大文件读取可以流式执行，无需在云端提供方中缓冲整文件；分页间版本变化会失败，不会拼接两个文件版本。
- 云端 preset 必须先加载身份适配器和 Device 客户端，再加载远程文件系统，并排除所有本地文件系统提供方。

## 已考虑的替代方案

- **把用户目录挂载到云端运行单元**：拒绝。普通云端部署没有通往用户文件系统的路径，而且会暴露主机特定路径。
- **直接在面向模型的工具中加入 Slark 逻辑**：拒绝。这样会重复文件系统语义并绕过提供方与政策 seam。
- **设备离线时回退到云端本地文件**：拒绝。同一虚拟路径会静默指向另一个文件系统。
