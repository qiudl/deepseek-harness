# Agent Note: 会话提示词发送方所有权

Status: implemented

[English](2026-10-29-session-prompt-routes.md) | 中文

## Problem

远程 Bot 聊天复用普通 Conversation，但通过通用端点向其会话发送会绕过 Bot 准入与稳定投递回执。客户端插件丢失时，不能静默改变发送权限。

## Decision

Client sessions 服务为每个会话身份注册一个显式提示词路由，业务方先注册再打开会话。路由保留原有输入请求与取消信号。业务方负责准入和接受结果；会话仍管理历史，输入框保留现有草稿行为。撤销路由会取消待处理调用，并留下页面生命周期内的撤销记录。只有从未注册的身份使用普通发送方。新的业务所有者可重新注册该身份；旧所有者的迟到结果仍被拒绝。

远程传输标志属于展示信息。远程工作区启动时把恢复交给首页所有者，避免在 Bot 身份解析前创建无关空会话。授权仍由 Host 与传输层负责。

## Alternatives considered

**增加第二套 Bot 输入框。** 这会重复草稿、输入、历史和无障碍行为。路由现有会话提示词可保留一套界面和原请求 ID。

**撤销后恢复通用发送方。** 这会把插件卸载或重连变成准入绕过。保留撤销记录让所有者缺失可见，直到有效替代者注册。

## Consequences

业务方必须先注册再导航，并随作用域销毁路由。页面在 sessions 服务关闭前保留已撤销身份。此机制不推断业务所有权，不授予远程控制权，不跨页面重载持久化未确认发送，也不改变子代理准入。业务所有者必须按原身份和回执核对未知结果。

## Testing

服务测试覆盖原请求身份、从未注册身份的普通发送、重复所有者、撤销、替换和迟到取消。工作区测试证明远程启动不自动恢复，仍允许主动导航。Bot 组合与手机抽屉浏览验证归属 REQ-20261018-0001。
