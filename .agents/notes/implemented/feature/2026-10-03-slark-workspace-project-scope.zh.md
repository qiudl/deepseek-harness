# Agent Note: Slark 工作区项目范围

Status: implemented

[English](2026-10-03-slark-workspace-project-scope.md) | 中文

## 问题

REQ-20260930-0004，项目212，T21 /22661。可选协同区域编辑会话实际 DSH 工作区的 Slark 项目限制，与任务发送分开。工作区初始没有项目，未归属工作区的会话不继承范围。

## 决策

范围模式关闭旧分配目录和旧调用入口；新项目范围不授权旧接口。Main 的范围和执行开关默认关闭。只有 Main 启用新版提交，且服务端确认目标支持独立执行时，范围内 Agent 才能作为候选选择；其他目录项仅供查看。普通聊天和已有任务历史仍可使用。

范围数据归属无 React 的会话投影，通过 slot 的 hooks 区域观察。工作区归属来自 Workspace Controller，未保存的选择属于组件私有状态；账号和 Native 权威保留在 Desktop Main。迟到读取不能恢复上一工作区或桥接身份的数据。保存使用当前权威版本，每次尝试后重新读取范围，不自动重放。

Desktop 草稿持久化只在按原 Profile 和会话隔离的加密存储中保留文本。浏览器分区继续使用临时存储，避免 Cookie 和运行时凭据随草稿持久保存。恢复序列化的 Agent 芯片也会恢复过期的受理权限，因此恢复的 `@` 名称保持普通文本，直到用户重新明确选择。版本检查拒绝过期写入者；确认结果不确定时停止写入，避免覆盖另一编辑器。通过 YAML 加载的输入框测试验证恢复、修改及清空文本、卸载和没有 Agent 调用。附件以及桥接接受写入前被中断的未保存编辑不在此保证范围内。

## 影响

明确的范围芯片将整条原始消息和 UTF-16 提及位置传给 Main，无需任务表单或确认预览。选择时的工作区、会话、目标、能力摘要与 UUID 绑定 Source。发送结果不确定时保留草稿和身份；编辑文字不会生成替代 Source，重新明确选择才建立新请求。Main 负责原始 Source 捕获、分析、冻结和受理；Client 只接收原始坐标与受理状态。受理不等于执行完成。Main 将终态回复持久化到原 Profile，验证安装身份签名的日志回执，再通过同一已授权 Account 和 Host 连接确认投递。

新版结果区域通过 Native 分页枚举已保存原文，再经 Main 获取该 Source 的只读授权结果。归属或 Connection generation 改变会清空页面数据；已加载历史页在刷新后保留。每条原消息独立拥有投递与计划读取窗口，最多并发读取两条；完整历史预算包含已加载的原消息页与回复页，不把全部原消息作为一项 30 秒操作。经过验证的原文与独立读取的回复在完整历史查询结束前发布，较慢历史不会隐藏其他已完成组。每次部分发布前校验显示顺序与整体预算；全部读取结束前保持加载中并禁用分页。同一 generation 回复在重新验证期间保持可见，读取失败或受限时独立清除该组。受限响应移除答案与目标名称，较旧投递版本不会回退已知状态。当前 Host 注册就绪时，Main 完成持久化和投递确认；否则结果保持待投递。渲染进程不接收签名回执，回复投递也不创建普通聊天轮次。

纯文字澄清只通过当前来源的明确选择进入既有触发链路。客户端从 Profile 的持久 Source 列表和 Main 的当前计划恢复问题；多个请求未决时，不会按最近一条代选。确定性被动回复身份不包含计划修订号，避免重新加载后为相同文字和未决项生成另一条 Source。Main 区分已经验证的澄清提交与任务受理；客户端在消费已记录回复前核对原消息和回复坐标。计划修订号增加本身不能证明这条回复已经提交。

聊天与侧栏模型只在同一桥和 Connection 身份下共享相同的进行中投递与计划读取。完成或失败后移除共享响应；再次刷新发起新的鉴权读取。关闭一个使用者不取消另一个使用者的观察。命令保持独立，不缓存已完成结果或签名。

## 考虑过的替代方案

只过滤旧分配列表而保留旧调用，会让缓存芯片或另一 renderer 调用绕过新项目限制，因此范围模式使用自己的当前权限目录和提交入口。

## 测试

验证覆盖模型生命周期、续页、组件多选/应用/取消，以及使用 Desktop 传输 fixture 的构建 AppWebEntry 组合。Native 签名、Main HTTP 协调和受限 PostgreSQL 在 Slark 的专用集成测试中验证；Profile-worker 归属读取、daemon inspection、Slark 认证和 Electron IPC 在该组合中仍为外部 fixture，不构成安装包或生产验收。

YAML 加载的来源与真实 SessionInputShell 覆盖范围候选选择、完整 Source 提交、同一身份的主动重试、工作区/归档/桥接变化、传输丢失，以及迟到或错误来源的受理响应。这些 Client 测试中的 Desktop 传输是 fixture，真实 Provider、工具与 GUI 闭环仍需验收。

真实 YAML 注册、SessionInputShell 受理事件与结果模型联动已覆盖；完整 128 KiB 纯文本结果通过 React DOM 验证。Native 冷 Profile 测试读回原始 journal 并验证分页和归属拒绝；它们仍使用服务端/Provider 替身，不证明实际模型或已安装 GUI 闭环。
