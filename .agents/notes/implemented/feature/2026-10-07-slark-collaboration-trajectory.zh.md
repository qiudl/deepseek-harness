# Agent Note: 原始 Session 协作轨迹

Status: implemented

[English](2026-10-07-slark-collaboration-trajectory.md) | 中文

## 问题

REQ-20261004-0008 要求用一个原始 DSH Trace ID 关联远端执行与反馈。本地 Session 事件无法独立证明远端结算、投递或消费。只有单独持久化的协作 Source 的 Session，在普通 Conversation 界面中仍被视为空白，因此视图标签被隐藏。

## 决策

Trajectory 提供 Session 级外部历史插槽。Slark 通过 Desktop Main 贡献经过授权的只读投影，以原始 Source 恢复根任务。云端审计序列与运行观察序列保持独立并分别分页。根任务状态、执行状态、投递和消费是不同的观察事实，缺少覆盖时明确说明。

Conversation 绑定可以通过可独立释放的贡献，为外部记录保留界面活动。Slark 在当前 Source 历史非空时保留该活动。这项贡献只影响展示，不会通过伪造 Session 事件、普通模型请求或执行 grant 使空对话显示为活跃。

## 考虑过的替代方案

**把云端审计复制到 Session 事件。** 这会为只读视图增加持久化模型历史义务，并重复保存需要独立授权的记录。

**要求先有普通聊天轮次。** 这会隐藏合法首次协作请求的轨迹，使原消息轨迹无法成为可用的验收入口。

**为 Slark 创建独立对话页面。** 第二套导航会把发起对话与执行反馈分开；由 Trajectory 所有者提供插槽可以保留原上下文。

## 结果

每次云端读取都重新校验权限；账号、工作空间和连接变化时清除缓存。Provider 内部过程仍不可观测，审计覆盖明确为部分。活动释放相互独立且幂等，Session 释放会清除这些贡献。验证覆盖空 Session 界面、插件释放、有界分页、迟到响应拒绝和组装后的轨迹入口；外部夹具不代表安装包与真实 Provider 已通过验收。
