# Agent Note: 收敛的持久化历史

Status: implemented

[English](2026-10-31-convergent-persistence-history.md) | 中文

## 问题

相互独立且已接受的变更可能从同一个 Session schema 出发并同时进入集成。替换任一确认记录会抹去已提交的转换，而单前驱历史无法同时保留两个分支并确定当前 schema。

## 决策

[目录内持久化历史决策](2026-09-11-persistence-type-history.zh.md)继续负责 schema 提取、逐根确认和定稿检查点保护。本决策仅对显式收敛的历史取代其单后继限制。

版本 2 确认记录可以为一个根指定具有共同祖先的不同前驱分支。变更后 schema 与每个父记录分别比较；每次转换必须包含变更、保持同一版本，且分类器不得要求额外兼容性复核。所有分支必须到达唯一末端记录。缺失父记录、冗余祖先、未合流末端、环，以及遗漏父记录的检查点均会导致验证失败。现有版本 1 声明与定稿记录摘要保持不变。

## 考虑过的替代方案

**改写一个已接受分支。** 这能形成线性链，但会改变已提交的确认记录及其历史比较。

**接受未合流分支。** 多个末端 schema 无法确定当前根，也不能证明任一分支如何到达当前状态。

**允许任意破坏性合流。** 多父确认会掩盖哪个前驱需要兼容性决策；限制为同版本合流可让此类变更继续使用单独评审的转换。

## 影响

作者保留两个父快照，只记录一次合流后的 schema。检查器验证每个父转换，但仅凭类型无法确定读取器行为；确认记录仍须记录兼容性证据。升版本合流需要单独排序的转换。[历史参考](../../../../docs/persistence-changes/README.zh.md#history-and-limitations)定义可接受的声明。
