# Agent Note: 原始 Root 的失败观察

Status: implemented

[English](2026-10-19-original-root-failure-observations.md) | 中文

## 问题

本机模型调用失败后，协调器仍可能保留任务的规划状态。如果无法读取本地观察，原对话会一直显示识别中，而重试可能重复提交尚未核实的任务。

## 决策

Host 通过单独协商的 `read_root_diagnostic` 命令公开已提交的分析失败。当前账号和 Profile 所有者读取已受理的原始 Root、Source 冻结的模型，以及原始或恢复日志中的有限观察。响应匹配原 Source 摘要和 Root 追踪，不包含提示词、输出、授权或异常文本，也不提供可执行句柄或重试权限。

结果模型仅在观察到任务持续规划、没有待答问题或 Agent 输出三十秒后，才在后台读取诊断。读取由既有刷新驱动；每个模型代际最多占用两个底层 IPC 读取名额，同一原消息两次读取完成后间隔三十秒。取消操作会保留名额，直至有期限的 Main 读取结束。交付结果的呈现不等待诊断。

交付页可能先于规划元数据返回。同一有权原消息的规划元数据尚未读完时，投影保留已有观察，不启动新的诊断读取。规划、澄清、输出或读取失败确定后，再应用既有资格规则。

协调器仍报告规划中时，原消息旁显示本地化的历史失败观察。该观察不修改协调器状态，也不宣告执行终止。Agent 输出或澄清问题会移除提示。账号、连接、工作区及视图生命周期变化会丢弃观察并忽略迟到响应。旧 Main 桥接不会收到诊断操作。

## 已考虑的替代方案

**用恢复操作做诊断。** 用户级恢复路径可能准备或恢复分析。独立的元数据能力使观察过程无法取得可执行句柄。

**用临时提示报告模型失败。** 尚未解决的原消息仍然存在时，临时提示会消失。日志支持的观察应当放在该消息旁，并可在重启后重新读取。

**先等待诊断再读取结果。** 额外的 Host 查询会延迟已经可读的 Agent 答复。独立的后台读取保留结果交付进度。

**把等待时长当作失败证明。** 较慢的服务仍可能成功。三十秒仅触发读取；只有匹配的已提交日志观察才产生失败提示。

## 影响

界面区分历史本地失败与协调器当前状态。空记录、不可用或不支持的诊断均不授权重试。有限原因省略服务方错误详情，初始观察窗口也会延迟旧规划失败的显示。

[诊断投影](../../../../packages/client/ui-slark-agent/src/client/collaboration-diagnostic.ts)负责限速与取消。[测试](../../../../packages/client/ui-slark-agent/tests/collaboration-diagnostic.client.spec.ts)覆盖有限解码、IPC 名额保留及迟到观察丢弃。结果模型测试证明尚未返回的诊断不会延迟 Agent 答复；视图测试保留原消息且不添加重试控件。这些检查证明观察与呈现行为，不证明安装客户端的工具执行或相对原生延迟。

[原会话协同轨迹](../feature/2026-10-07-slark-collaboration-trajectory.zh.md)继续负责云端审计和执行观察，本地失败补充该历史。
