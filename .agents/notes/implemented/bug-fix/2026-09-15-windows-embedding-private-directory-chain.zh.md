# Agent Note: 按顺序创建 Windows 嵌入私有目录链

Status: implemented

[English](2026-09-15-windows-embedding-private-directory-chain.md) | 中文

## 问题

Windows 原生私有目录操作一次只创建一个目录，并在直接父目录不存在时失败。全新安装的 Desktop 会提供应用目录下的深层环境路径，而该应用目录本身可能尚不存在，因此安装身份准备可能在创建任何 DSH 存储之前失败。

## 决策

身份准备同时接收 DSH 私有存储根目录与所选环境根目录。它只递归创建存储根目录的普通应用父目录，随后用原生 SID 私有操作按顺序创建并验证存储根目录、其 `environments` 子目录、以 SHA-256 命名的环境根目录以及 identity 子目录。环境根目录必须是所提供存储根目录下的直接命名空间子目录。

## 考虑过的替代方案

**使用普通文件系统 API 递归创建环境根目录。** 未采用，因为中间 DSH 目录会绕过原生 owner、DACL 和重解析点验证。

**把私有 DACL 应用到驱动器根目录之前的所有祖先目录。** 未采用，因为 DSH 不拥有操作系统目录和用户 Profile 目录，不得改变其访问策略。

## 影响

首次启动可以在不削弱私有存储检查的情况下创建尚不存在的 DSH 目录层级。已有安全目录仍可复用；环境根目录位于所提供存储命名空间之外，或任何私有目录证据不安全时，仍会在接受身份文件前失败。
